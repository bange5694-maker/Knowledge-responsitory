## 三、发现的问题

### 问题 1：5.3 表多了一条 `nav.html → nav_node` 的包含关系

- **说明书位置**：5.3 表第 5 行
- **原文**：`share_layout/nav.html` 包含 `share_layout/nav_node.html` / `nav_node_mobile.html`
- **实际代码**：
  - `templates/share_layout/nav.html` 第 42、44、207、209 行使用 `{% query nav_category_list ... %}` 直接渲染分类，全文没有 `{% include "share_layout/nav_node..." %}`；
  - `templates/share_layout/nav_node.html` 只在自身第 11 行用 `{% include template_name %}` 递归包含自己；
  - 全仓库（排除 `doc/` 与两个 nav_node 文件）对 `nav_node` 的引用数为 **0**。
- **性质**：错误依赖，会让读者以为导航主链路依赖旧版片段。

### 问题 2：5.3 表漏了 `comment_list.html → comment_item_tree.html`

- **说明书位置**：5.3 表
- **实际代码**：`templates/comments/tags/comment_list.html` 第 19 行：
  ```django
  {% include "comments/tags/comment_item_tree.html" %}
  ```
- **性质**：漏记；该模板属于旧版评论链路，当前界面未使用，但仍是一条真实的 include 关系。

### 问题 3：6.1 包图把 `account` 包整体画成继承 `base_account.html`

- **说明书位置**：6.1 图、6.2 表、附录 A.3
- **实际代码**：
  - `account/login.html`、`registration_form.html`、`forget_password.html` 第 1 行 → `share_layout/base_account.html`；
  - `account/result.html` 第 1 行 → `share_layout/base.html`。
- **矛盾点**：5.2 表明明写对了 `result.html → base.html`，但 6.1 图 / A.3 的 `AFILES → BASEACC` 把整个包画成只连 `base_account`。
- **性质**：包级抽象丢失了例外，和 5.2 表冲突。

### 问题 4：6.1 包图把 `oauth` 包整体画成继承 `base.html`

- **说明书位置**：6.1 图、6.2 表、附录 A.3
- **实际代码**：
  - `oauth/bindsuccess.html` 第 1 行 → `share_layout/base.html`；
  - `oauth/require_email.html` 第 1 行 → `share_layout/base_account.html`；
  - `oauth/oauth_applications.html` 是被 `load_oauth_applications` 渲染的片段，**不继承任何母版**。
- **矛盾点**：5.2 表写对了两个继承目标，6.1 图 / A.3 的 `OFILES → BASE` 只画了 `base.html`。
- **性质**：同问题 3，包级箭头过度简化。

### 问题 5：5.1 没有标注 `nav_node*.html` 已不再被引用

- **说明书位置**：5.1 基础布局表
- **原文**：`nav_node.html`、`nav_node_mobile.html`：递归渲染分类树的导航片段（含嵌套子分类）
- **实际**：功能描述本身没错，但这两个文件当前没有任何外部引用；配合 5.3/6.1 的错误边，会让人误以为它们是导航主链路。
- **性质**：文档准确性问题，建议补“旧版，当前未被引用”。
