## 2 前置条件与后置条件

**前置条件（Pre-conditions）**

1. 用户已注册并处于登录状态；
2. 目标文章存在且处于可见状态；
3. 该文章未关闭评论功能（文章评论开关为开启）。

**后置条件（Post-conditions）**

1. 评论已持久化保存，并与文章、发表用户（以及可能的父评论）正确关联；
2. 评论在文章评论区立即可见，或进入"待审核"队列（取决于站点的评论审核设置）；
3. 页面刷新后自动定位到新发表的评论；
4. 系统已向评论者（以及被回复者）异步发送邮件通知，发送结果记入邮件发送日志；
5. 侧边栏「近期评论」等缓存已刷新。

## 3 基本事件流（主成功场景）

| 步骤 | 事件 |
|---|---|
| 1 | 注册用户打开某篇文章的详情页，系统显示文章正文、评论列表与评论输入框； |
| 2 | 用户点击评论输入框，输入评论内容（正文不超过 300 字，支持 Markdown 语法）； |
| 3 | 用户点击「发表评论」按钮，提交评论； |
| 4 | 系统校验用户身份（登录状态）与文章评论开关，均合法； |
| 5 | 系统校验评论内容合法（非空、长度不超过 300 字）； |
| 6 | 系统保存评论，自动关联当前文章与当前用户；若提交数据中带有父评论标识，则同时关联父评论（此分支由子用例「回复评论」执行）； |
| 7 | 系统根据站点设置决定评论可见性：未开启评论审核时，评论立即启用并可展示； |
| 8 | 系统刷新页面，并自动定位到新发表的评论； |
| 9 | 系统异步发送通知邮件：向评论者发送"评论成功"通知；若本次为回复，同时向被回复评论的作者发送"收到回复"通知；发送结果记入邮件发送日志； |
| 10 | 用例结束。评论区（或待审核队列）中出现该评论。 |

## 4 备选事件流

| 编号 | 触发条件 | 处理 |
|---|---|---|
| 4a | 用户未登录（或登录会话已失效） | 系统提示"请先登录后发表评论"并跳转登录页；登录成功后返回原文章页，回到基本事件流第 2 步重新开始 |
| 7a | 站点开启"评论需审核"设置 | 评论保存为"待审核"状态，暂不在评论区显示，系统提示用户评论已提交等待审核；管理员在后台审核通过后评论对外可见 |
| 9a | 通知邮件发送失败（如邮件服务不可用） | 系统在邮件发送日志中记录失败结果，不中断用例——评论发布不受影响 |

## 5 异常事件流

| 编号 | 触发条件 | 处理 |
|---|---|---|
| 4b | 该文章已关闭评论（文章评论开关为关闭） | 系统提示"该文章评论已关闭"，用例终止 |
| 5a | 评论内容为空，或超过 300 字 | 系统提示内容校验错误，页面停留在原位置，返回基本事件流第 2 步修改后重试 |
| 6a | 文章在提交瞬间已被删除（并发情形） | 系统返回 404 错误页，用例终止 |

## 6 业务规则

| 编号 | 规则 |
|---|---|
| BR1 | 评论必须由已登录的注册用户发表，匿名用户不可发表评论 |
| BR2 | 评论正文为 1~300 字，支持 Markdown 语法 |
| BR3 | 评论是否立即显示由站点设置"评论是否需要审核"决定：不审核则立即显示，需审核则先进入待审队列 |
| BR4 | 回复评论必须挂在同一篇文章的某条父评论之下，支持逐层嵌套（无限层级） |
| BR5 | 评论保存后，系统异步发送邮件通知（评论者；回复时还包括被回复者），并记录邮件发送日志 |
| BR6 | 文章可单独设置关闭评论，关闭后系统拒绝一切新评论 |

## 7 非功能需求

1. **性能**：点击发表后 2 秒内完成响应；邮件通知异步发送、不阻塞页面返回；
2. **可扩展**：评论区支持无限嵌套渲染，列表查询已建索引，翻页与嵌套下性能稳定；
3. **安全**：发表评论需携带 CSRF 令牌；评论内容经模板转义与 Markdown 渲染，防止 XSS；
4. **可用性**：未登录用户看到"登录后可评论"的提示与登录入口，不出现无响应操作。

## 8 与其他用例的关系说明（与用例图对应）

1. **继承**：本用例是父用例；「回复评论」是它的子用例——回复=在本用例行为基础上增加"关联父评论、通知被回复者"；
2. **前置依赖**：「用户登录」是本用例的前置条件（用例图中两者都是注册用户的关联用例，未登录情形见备选流 4a）；
3. **协同**：「管理评论」——当站点开启审核时，待审核评论由管理员在后台审核后对外可见；
4. **相关**：「评论表情回应」对已发表的评论进行表情互动，与本用例共用评论区界面。
