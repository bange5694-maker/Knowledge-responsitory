1. 界面的截图、界面之间怎么跳转 → 说明书 **第 2、3、4 章**；

## 二、每人的检查方法（照着做就行）

### 1. 计划经理（姓名待填）—— 检查「界面怎么跳转」

**检查什么**：说明书第 4 章有一张表，写着 11 条「从哪个界面 → 点哪里 → 跳到哪个界面」。你要确认每一条和网站实际情况一样。

**怎么做**：

1. 打开网站 `http://127.0.0.1:8001`（打不开就找组长）；
2. 打开说明书的第 4 章，从第 1 条开始，在网站上照做一遍（比如第 1 条写「首页点文章标题 → 进入文章详情」，你就真的去点一下）；
3. 能跳对 → 打勾；跳不到、或者描述不对 → 说明书写错了，把说明书改成正确的；
4. 11 条全部查完，写一份检查记录（模板在文末）。

**交什么**：检查记录；如果改了说明书，一起提交。

---

### 2. 质量和过程经理（姓名待填）—— 检查「4 张模板关系表」

**检查什么**：说明书第 5 章有 4 张表（模板功能表、继承表、包含表、标签对照表），确认表里写的和项目实际文件一致。

**怎么做**（用 VS Code，操作方法和上次改页脚的作业一样）：

1. 用 VS Code 打开项目文件夹；
2. 按 `Ctrl + Shift + F` 打开全局搜索，逐个核对：
   - 搜 **extends** → 对照「继承表」（表里一共 12 条）；
   - 搜 **include** → 对照「包含表」；
   - 打开 `blog/templatetags/blog_tags.py`，搜 **inclusion_tag** → 对照「标签对照表」；
3. 一致 → 打勾；不一致 → 把说明书改成正确的；
4. 写检查记录。

**交什么**：检查记录；如果改了说明书，一起提交。

---

### 3. 支持经理（姓名待填）—— 检查「界面清单和截图」

**检查什么**：说明书第 2.3 节是一张界面清单（13 条），第 3 章是 13 张截图和对应的文字说明。确认：清单、截图、文字三者都能对上。

**怎么做**：

1. 打开说明书第 2.3 节和第 3 章（可以在 GitHub 上看，也可以把仓库下载到电脑上看）；
2. 一条一条对：
   - 清单里写的截图文件，在 `doc/imgs/screens/` 文件夹里真的有吗？
   - 文字说明里提到的界面元素，截图里真的能看到吗？（比如说明写「顶部有搜索框」，截图上真有吗？）
3. 发现错别字、写错的地方，直接改掉；
4. 写检查记录。

**交什么**：检查记录；如果改了说明书，一起提交。

---

### 4. 开发经理（席佳宁）—— 检查「UML 包图」

**检查什么**：说明书第 6 章的包图（哪些网页文件属于哪个「包」、包和包之间怎么引用）画得对不对；然后把 3 张关系图重新生成一遍。

**怎么做**：

1. 打开说明书第 6 章，对照第 5 章的表格看包图对不对。重点看一个地方：账户页指向的是 `base_account`，不是 `base`——这是两套不同的母版，别搞混；
2. 核对 5.5 插件表：打开 `plugins` 文件夹下各个插件的 `plugin.py`，搜 `hooks.register`，和表格里的「插件 → 钩子」逐个对比；
3. 重新生成 3 张图（简单方法）：
   - 打开网址 <https://mermaid.live>；
   - 把说明书**附录 A** 里对应的代码整段复制进去；
   - 在页面右侧导出 PNG 图片；
   - 用新图片替换 `doc/imgs/diagrams/` 里的这 3 张图。
4. 写检查记录。

**交什么**：检查记录 + 新的 3 张 PNG 图。

## 三、几条要注意的

1. **一人一个分支**：从 main 建自己的分支（名字建议 `review-你的名字`），只改自己负责的部分；
2. **别动别人的部分**：发现别人负责的内容有问题，写在自己的检查记录里，交给对应的人去改；
3. **提交说明写清楚**：例如「复核第 4 章：全部正确」或「复核第 4 章：改了第 7 条」；
4. **有问题先发群**：搞不定别硬扛，截图发到群里问组长；
5. **时间**：两天内完成各自的检查，第三天组长交最终版（具体看群通知）。
