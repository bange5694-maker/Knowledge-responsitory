## 〇、当前状态与分工思路

说明书**初稿已由组长完成**（`doc/界面设计说明书.md`），包含 13 张界面截屏、界面流转图、界面思维导图、UML 模板包图、模板功能/继承/包含/tag 关系表等全部内容。

本次分工是**全组复核与补全阶段**：把说明书拆成**边界清楚、工作量相当的 4 块 + 统稿 1 块**，每人独立负责一块，逐项与代码/实际界面核对，发现问题当场修正，并留下自己的《核对记录》作为个人贡献证明（提交到自己的分支）。

**为什么工作量差不多**：每人的核对对象数量和预估时长基本一致（见下表），都不超过约 3 小时，且不需要其他人配合即可独立完成。

**完成标准**：11 条路径全部有核对结论；流转图与代码一致；《核对记录》提交。

### 任务 2 ｜质量和过程经理（姓名待填）：模板关系表格复核

**目标**：确认说明书第 5 章四张表格逐行与实际模板代码一致。

**具体步骤**：

1. **5.1 模板功能表**：逐个打开 `templates/` 下的 38 个模板，核对功能描述是否准确；对标注「未引用/旧版」的模板（`comment_list.html`、`comment_item.html`、`comment_item_tree.html`、`post_comment.html`、`adsense.html`），在仓库内全局搜索文件名，确认确实没有被引用；
2. **5.2 继承表**：打开每个页面模板，核对第 1 行的 `{% extends %}` 与表格一致（共 12 条）；
3. **5.3 包含表**：全局搜索 `{% include %}`，核对宿主模板、被包含模板与说明（注意评论模板的自包含递归、`nav_node` 的递归）；
4. **5.4 tag 映射表**：打开 `blog/templatetags/blog_tags.py`、`comments/templatetags/comments_tags.py`、`oauth/templatetags/oauth_tags.py`，逐个核对 `@register.inclusion_tag('xxx.html')` 与表格的「标签 → 模板」映射一一对应；
5. 修正发现的错误（直接改文档表格），填写《核对记录》（逐表：通过 / 修正了什么）。

**完成标准**：四张表逐行核对完毕；不一致处全部修正；《核对记录》提交。

## 三、协作与提交要求

1. **一人一分支**：从 main 建立自己的分支（建议命名 `review-<姓名拼音>`），**只修改自己负责的章节/文件**，完成后推送并创建 PR，由组长合并；
2. **不越界**：发现自己负责章节之外的问题，不要直接改（避免冲突），写在《核对记录》里交给对应负责人；
3. **提交说明**：写清楚「复核第 X 章：修正了…… / 全部通过」；
4. **核对记录**：每人提交一份 `doc/核对记录-<章节>-<姓名>.md`（或在 PR 描述中写明），内容包括：核对对象、结论、修正明细、证据（截图/代码行号）；
5. **时间安排**（以群通知为准）：第 1–2 天各自完成复核并提交 PR，第 3 天组长统稿、提交最终版；
6. **遇 Git 报错**：按《作业分工与操作指南.md》第六章「报错急救包」处理，先截图发群，不要自己乱试。
