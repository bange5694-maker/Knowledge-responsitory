## 1 作业要求与本文用途

作业要求：**手工绘制**本系统的用例图（按教材 5.5.3 语法），拍照/截图提交；另选一个核心用例按教材 5.5.4 撰写用例说明。

本文用途：把"图上画什么、每一笔怎么画"全部列清楚。**照本文清单 + 参考图摆位，手绘不会出错**。参考图是把本文内容用绘图脚本精确画出来的成品，手绘时把它摊在旁边，逐元素照描即可。

老师讲的语法三要素（原文要点）：

1. **执行者**：系统之外、使用系统功能并与系统交互信息的外部实体；
2. **用例**：执行者要达成一项相对独立完整业务目标所要求系统完成的功能；
3. **关系**：用边连接执行者与用例（执行者能"观察"到该业务就连一条边）、用例与用例；用例之间的关系必有**包含、扩展、继承**三种。

## 2 图上要画的全部元素（总计：6 执行者 + 22 用例 + 26 条边）

### 2.1 执行者（6 个，画火柴人）

| 执行者 | 类型 | 为什么是执行者（都在系统之外） |
|---|---|---|
| 访客 | 人 | 未登录的浏览者，使用浏览/搜索功能 |
| 注册用户 | 人 | 注册并登录后的用户，可参与评论互动 |
| 管理员 | 人 | 通过后台维护数据的人（本系统后台为独立管理站点） |
| 第三方登录平台 | 外部系统 | 提供 OAuth 授权的外部平台（如 GitHub 等），登录流程要靠它授权 |
| 邮件服务器 | 外部系统 | 系统通过它发注册激活邮件、找回密码验证码、评论通知邮件 |
| 微信服务器 | 外部系统 | 公众号机器人消息的中转平台（微信问答功能） |

> 注：第三方登录平台/邮件服务器/微信服务器是"外部系统"型执行者，也统一画成火柴人即可（教材通用画法）；若教材要求外部系统画成矩形，改成矩形框同样正确。

### 2.3 关系（26 条边，类型与方向都在此表）

**（1）关联（执行者—用例，共 18 条；实线，不画箭头）**

| 执行者 | 连到哪些用例 |
|---|---|
| 访客 | 搜索文章、浏览文章列表、查看文章详情、查看友情链接 |
| 注册用户 | 注册、用户登录、找回密码、退出登录、发表评论、评论表情回应 |
| 管理员 | 后台登录、维护文章、管理评论、管理用户、站点设置 |
| 第三方登录平台 | 第三方登录 |
| 邮件服务器 | 发送验证邮件 |
| 微信服务器 | 微信问答 |

> 关键规则：**不要**给"子用例/被包含用例/扩展用例"重复连执行者。注册用户不连"第三方登录"（它继承自"用户登录"）、不连"回复评论"（它继承自"发表评论"）、不连"发送验证邮件"（它是被包含的）；访客不连"按分类浏览/按标签浏览"（它们是扩展用例）。这不是漏画，而是标准画法。

**（2）包含（共 2 条；虚线 + 开放箭头 + 标注"包含"）**

| 起点（基础用例） | → 终点（被包含用例） | 理由（答辩可用） |
|---|---|---|
| 注册 | → 发送验证邮件 | 注册后系统必然发送邮箱激活邮件，是必经子步骤 |
| 找回密码 | → 发送验证邮件 | 重置密码必须使用邮箱收到的验证码（5 分钟内有效） |

**（3）扩展（共 3 条；虚线 + 开放箭头 + 标注"扩展"）**

| 起点（扩展用例） | → 终点（基础用例） | 理由（答辩可用） |
|---|---|---|
| 按分类浏览 | → 浏览文章列表 | 在浏览列表的过程中，按分类筛选是可选插入的行为 |
| 按标签浏览 | → 浏览文章列表 | 同上，按标签筛选也是可选插入的行为 |
| 补充邮箱 | → 第三方登录 | 仅当第三方平台未返回邮箱时才发生（条件性插入） |

**（4）继承/泛化（共 3 条；实线 + 空心三角箭头）**

| 子 | → 父 | 说明 |
|---|---|---|
| 第三方登录 | → 用户登录 | 第三方登录是登录的一种特化，继承登录的内容 |
| 回复评论 | → 发表评论 | 回复是发表评论的一种（多一个"挂到父评论下"） |
| 注册用户 | → 访客 | 执行者泛化：注册用户天然拥有访客的全部用例，不必重复连线 |

> **方向口诀（最容易画反）**：包含的箭头 → 指向"被包含者"；扩展的箭头 → 指向"被扩展的基础用例"；继承的空心三角 → 指向"父"。三角必须画**空心**（涂黑就错了）。

## 3 符号画法速查（对照教材）

| 元素 | 画法 |
|---|---|
| 执行者 | 火柴人：圆头 + 竖身 + 两臂 + 两腿；名字写在**下方** |
| 用例 | 椭圆；名字写在椭圆**内部**；动宾短语（如"发表评论"） |
| 系统边界 | 大矩形；系统名「知识分享博客系统」写在框**顶部居中**；执行者在框外，用例在框内 |
| 关联 | 实线，**无箭头**（老师：执行者能观察到该业务就连一条边） |
| 包含 | 虚线 + 开放箭头（只画两根短线，不涂实）+ 文字"包含" |
| 扩展 | 虚线 + 开放箭头 + 文字"扩展" |
| 继承 | 实线 + **空心三角**箭头；可不写字（写"继承"也行） |

> 若教材用的是 «include» / «extend» 英文构造型写法，把文字"包含/扩展"替换成 «include»/«extend» 即可，含义与箭头方向完全不变。

## 4 布局建议（照参考图摆放）

**整体**：A4 横放（A3 更宽裕）。左边一竖列三个小人，右边一竖列三个小人，中间大矩形是系统边界，边界内自上而下四个"分区"。

| 分区 | 内容（从左到右） | 摆位要点 |
|---|---|---|
| ① 内容浏览（最上） | 第 1 行：搜索文章、浏览文章列表、按分类浏览；第 2 行：查看文章详情、查看友情链接、按标签浏览 | 「浏览文章列表」放中列略偏上，两条"扩展"虚线从右上/右中拐进它；访客的 4 条实线连到 搜索文章、浏览文章列表、查看文章详情、查看友情链接 |
| ② 账户与互动（中部） | 第 1 行：注册、用户登录、第三方登录（补充邮箱最高最右）；第 2 行：找回密码、发送验证邮件；第 3 行：退出登录、发表评论、回复评论；第 4 行：评论表情回应 | 「发送验证邮件」靠右，正对邮件服务器；两条"包含"虚线都指向它；「第三方登录」靠右，正对第三方登录平台 |
| ③ 后台管理（左下） | 一竖列五个：后台登录、维护文章、管理评论、管理用户、站点设置 | 管理员小人对准这一列的中部，5 条实线呈扇形连过去 |
| ④ 微信服务（右下） | 微信问答 | 摆在右下方空白处，正对微信服务器 |

执行者位置：**左列**（上→下）访客 / 注册用户 / 管理员；**右列**（上→下）第三方登录平台 / 邮件服务器 / 微信服务器。左列在「访客」与「注册用户」两个小人之间画一条**竖直实线**，上端（靠访客一侧）画**空心三角**并标"继承"（即 2.3 表中的执行者泛化）。

## 5 手绘步骤（照着做，约 30~40 分钟）

1. 纸横放，用**铅笔轻画**全部内容（先别用黑笔）；
2. 画系统边界大矩形，顶部写「知识分享博客系统」；
3. 按分区摆 22 个椭圆：先用铅笔写名字占位，检查椭圆之间不挤、不叠；
4. 左列画 3 个小人、右列画 3 个小人，写入名字；
5. 先画 18 条**关联实线**（再三确认：一根箭头都不要画）；
6. 画 2 条**包含**、3 条**扩展**：虚线要"一笔一段"地画成均匀虚线，箭头只画两笔开口，旁边写"包含/扩展"；
7. 画 3 条**继承**：实线 + 空心三角（三角内不涂色）；
8. 擦净铅笔稿，黑笔描清；在图下方或右下角写题头（图名、姓名、学号、日期），格式如：
   `图 4-1 「知识分享」博客系统用例图  第 13 组 ×××  学号 ×××  2026-10-11`
9. 拍照/扫描：正对纸面、光线均匀、四角完整、字迹清晰；建议拍两张（一张全景、一张局部清晰）择优提交。

## 8 为什么这么画（答辩自问自答）

- **为什么"注册/找回密码"包含"发送验证邮件"？** 这两个流程里邮件是必经步骤（注册要邮箱激活才能登录；找回密码必须用邮箱验证码），是必然执行的子功能——包含。
- **为什么"补充邮箱"是扩展而不是包含？** 它只在第三方平台没有返回邮箱时才执行（有条件、可选），插在"第三方登录"流程中——扩展。
- **为什么"第三方登录"继承"用户登录"？** 它本质是登录的特化形式，具备登录的全部内容并加上"跳转第三方授权"——继承。
- **为什么访客不用连"按分类浏览/按标签浏览"？** 它们是"浏览文章列表"的可选变体（扩展用例），关联由基础用例承担，扩展用例不重复连线。
- **为什么邮件服务器是执行者？** 它在系统之外，但系统发邮件必须与它交互信息（交互对象是外部实体）——符合执行者定义。
